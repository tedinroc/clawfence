ClawFence

Fewer interruptions. Zero surprises. An intent firewall for OpenClaw.

The problem

Approvals are exhausting, so people turn them off. Then one poisoned file can delete Documents or POST an SSH key. The missing layer is not another approval button — it is knowing what the task actually authorises.

The mechanism

  • Intent card from the task: named paths, domains, recipients, effect classes, spend cap.
  • Action tuple for every tool call: reads, writes, deletes, URLs, recipients, data-out, privilege.
  • Rules first: out-of-scope writes/deletes/egress/secrets block. Only ambiguity reaches a decision model.
  • Pause / arbiter: hold the call; approve resumes it, deny blocks it, STOP aborts the run.
  • Hash-chained audit: intent → action → verdict → reason → approver.

The adjudicator never sees tool output or page text. Injected content has no channel into the decision.

  • Dress rehearsal on local Qwen3-4B: pause card 6.4 s, approve→done 2.1 s, secret block 1.55 s.
