CLAWFENCE // ONE HOOK, ONE CONTRACT

Scope before action, not after damage.

Every tool call is checked against the task's intent card before it runs.

1 · INTENT

Task contract

Derived from the user's message, conservatively: named paths, domains, recipients, effect classes. Unclear authority stays out.

2 · ACTION

Typed tuple

exec command, patch paths, file writes, URLs, message targets, MCP args. Effects and reversibility are explicit.

3 · DECISION

Rules first

Out-of-scope writes/deletes, unapproved egress, secrets, privilege: blocked with a code and a reason. Optional decision model only for ambiguity.

4 · HUMAN

Physical arbiter

A phone, tablet or Cardputer gets the action card: task, tool, target, reason. One tap approves or denies. A deny is recorded; an approve is a one-action grant bound to the hash.

5 · EVIDENCE

Hash-chained audit

intent hash → action hash → verdict → reason → approver. clawfence verify recomputes the chain. This is the receipt for an autonomous run.

The adjudicator never sees tool output or page text. Injected content has no channel into the decision.
